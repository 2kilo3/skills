# 全阶段验收清单（Checklist）

> 每个 Phase 结束时对照本清单。学习者主动跳过验证时可继续，但必须把该阶段标记为“未验证”，且最终不得宣称通过毕业验收。
> Phase 7 结束时执行"最终 8 问"；Phase 9 结束时执行"毕业复核"。
> 产出纪律：中间信息只进入 `notes/working.md`；快速导览默认无文件，深度带读只交付 `notes/guide.md`，完整实战只交付 `notes/guide.md` + `notes/course.html`。

## 阶段门禁

### Phase 0 完成标准
- [ ] 项目来源已确定（本地路径 / GitHub 已 clone / 当前目录）
- [ ] 学习目标层级已选定（整体 / 子系统 / 功能 / 一次调用）
- [ ] 学习者 Git 基础已确认或已补课
- [ ] 学习工作区与目标仓库分离，或学习者已明确同意在仓库内写入
- [ ] 运行、安装、写学习文件、改源码、建分支、提交代码的权限已分别记录
- [ ] commit SHA、shallow 状态和初始 `git status` 已记录
- [ ] `notes/working.md` 已创建并记录学习目标

### Phase 1 完成标准
- [ ] 已阅读 README 与核心文档并提炼要点
- [ ] 5 个基本问题有明确答案
- [ ] 学习者用自己的话写出"一句话项目描述"（不是复读标题）
- [ ] working.md 已记录 5 问答案 + 一句话描述

### Phase 2 完成标准
- [ ] 顶层目录职责已明确（能回答"这个仓库大概怎么组织的"）
- [ ] 关键配置文件已识别，技术栈已列出
- [ ] 构建/测试命令已记录；扩展机制（继承/插件/注册）已识别
- [ ] 学习者能回答"哪个目录是核心实现""用了什么存储"
- [ ] working.md 已记录目录职责表 + 技术栈 + 扩展机制

### Phase 3 完成标准
- [ ] 项目已在本地成功运行（有运行成功的证据）
- [ ] 学习者亲手使用过项目（CLI 命令 / 页面操作 / example / demo）
- [ ] 若无法安全运行，已切换静态证据模式并明确未验证结论
- [ ] 安装、外部服务或临时源码修改均在相应授权范围内
- [ ] 排错过程与临时修改已记录（临时修改标记待恢复）
- [ ] working.md 已记录启动步骤、运行证据、踩过的坑

### Phase 4 完成标准
- [ ] 1-3 条目标相关行为流程已梳理（含学习者复述）
- [ ] 数据模型已理解（表关系 / 数据结构 / schema）
- [ ] 学习者能描述"点 X 之后系统发生了什么"
- [ ] working.md 已记录流程 + 数据模型

### Phase 5 完成标准
- [ ] 3-6 个核心名词已提炼并写明职责
- [ ] 一句话架构成立（"A 创建 B，B 调用 C，C 管理 D"）
- [ ] 架构图草稿已画出（含学习者参与；Phase 7 用 mermaid 精化）
- [ ] working.md 已记录核心名词 + 一句话架构

### Phase 6 完成标准
- [ ] 学习者选定一条功能链路
- [ ] 调用链从入口到末端已完整追踪（每层有文件+函数+**行号**+职责）
- [ ] 至少用 1 个测试验证过理解
- [ ] 历史可用时至少用 1 次 `git blame`/PR 解释“奇怪代码”；不可用时已记录原因
- [ ] 学习者能不看代码复述链路
- [ ] working.md 已记录 1-3 条调用链

### Phase 7 完成标准（学习检查点）
- [ ] 最终 8 问达到阶段阈值；未通过项已回炉或标记 `unverified`
- [ ] 深度带读模式已生成并预览 `notes/guide.md`
- [ ] `validate_artifacts.py guide` 返回 0
- [ ] 最终成功校验后 guide 未再修改；若修改已重跑校验
- [ ] 深度带读模式的 3 个随机导航任务全部找到对应文件与函数
- [ ] 完整实战模式已冻结证据和任务候选，未提前生成最终交付物

若学习者跳过验收，允许以前三项替代为：暂定 guide 已生成、校验返回 0、文档明确标注“学习验收未完成”。此分支的 Phase 7 状态必须为 `unverified`，导航任务不得勾选通过。

### Phase 8 完成标准
- [ ] 修改源码已获得明确授权
- [ ] 至少完成一项 L3/L4/L5 或同等复杂度的实质任务
- [ ] 每个任务都运行验证过（不是只改代码）
- [ ] 每个任务都跑过相关测试
- [ ] 如创建分支或 commit，均有对应授权；已提交时 commit 边界清晰
- [ ] 修改记录已写入 working.md，等待 Phase 9 汇总

### Phase 9 完成标准
- [ ] 全量测试与学习前基线相比没有新增失败
- [ ] `git diff` 审查完成，无调试残留
- [ ] Phase 3 临时修改已恢复
- [ ] 毕业复核 8 问完成（见下）
- [ ] `guide.md` 与 `course.html` 已基于最终源码快照生成并预览
- [ ] `validate_artifacts.py guide` 与 `course` 均返回 0
- [ ] 最终成功校验之后两份交付物均未再修改

## 最终 8 问（Phase 7 门禁）

对学习者逐题提问，答案指向具体文件/函数为佳：

1. 这个项目解决什么问题？（给谁用、解决什么痛点）
2. 程序从哪里启动？（入口命令 / 入口文件 / main 函数）
3. 核心模块有哪些？（各负责什么）
4. 一次典型请求/操作如何经过整个系统？（说或画出完整链路）
5. 最重要的几个抽象是什么？它们之间什么关系？
6. 测试在哪里？怎么运行？
7. 举 1 个例子说明"为什么这样设计"？（有 git 历史或 PR 依据更佳）
8. 如果要修改某功能，应该从哪里开始？（用 guide.md 导航表指出起点）

每题按以下量表评分：

- **0 分**：无法回答、明显错误或包含编造内容。
- **1 分**：概念正确，但不能给出代码或运行证据。
- **2 分**：答案正确，并能指向已验证的文件、符号、命令或运行结果。

阶段通过：总分至少 12/16，且第 2、4、8 题均不低于 1 分。未通过题回炉对应 Phase；学习者拒绝回炉时标记 `unverified`。

## 毕业复核（Phase 9，比 Phase 7 要求更高）

- [ ] 8 问总分至少 14/16，且第 2、4、8 题均为 2 分
- [ ] 学习者能独立描述自己完成的每个修改任务（为什么改、改哪、怎么验证）
- [ ] 实质修改最多接受两次提示，定向测试通过且全量测试无新增失败
- [ ] 学习者能指出至少 1 处“我原本理解错了，现在修正了”的地方
- [ ] 下一步学习路线已给出（新链路 / 更深子系统 / 参与贡献）

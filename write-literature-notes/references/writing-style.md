# 写作风格与字段合同

## 核心原则

固定的是 Word 表格字段和证据要求，不是每一栏的点数、标题或句式。论文原文决定具体内容；老师参考稿和用户既有笔记只控制组织方式、简洁程度与表达习惯。

证据优先级：

1. 论文原文、补充材料与正式出版页；
2. 老师提供的参考笔记；
3. 用户既有阅读笔记；
4. 基于上述材料的概括。

资料冲突时以论文原文为准。无法核验的内容留空或填写 —，不做推测。

## 总体语气

- 使用简洁、直接的中文学术说明文；一条内容尽量完成一个信息任务。
- 先写事实和机制，再写结论；保留必要的算法名、数据集名、指标和数字。
- 尽量少用引号、比喻、口号、箭头和过度包装的概念，减少明显的生成式写作痕迹。
- 避免赋能、颠覆性、全方位、值得注意的是、充分彰显、毋庸置疑等宣传式或模板化表达。
- 不连续使用首先、其次、此外、最后来制造形式层级；层级应来自论文真实结构。
- 显著只用于统计检验或论文明确报告的统计结论。

## 分点格式

- 研究问题、研究方法和研究结果只有一个完整要点时直接写成一段，不加编号；同一字段有两个及以上独立要点时，每点单独成段，依次使用 `1. `、`2. `、`3. `。
- 创新与不足分别计数：创新只有一个点时不编号，两个及以上创新点才从 `1. ` 开始编号；不足使用同一规则，并从自己的 `1. ` 重新开始。
- 编号后直接进入完整句子，不再添加“问题一”“方法：”等短标签。
- JSON 数组中只写正文，不写“创新：”“不足：”或手工编号；生成脚本按每个字段或分组的实际点数统一编号。

## 字段合同

### 题目、作者、类型、来源、链接、关键词

- 题目和作者按论文首页原文填写，不自行翻译、缩写或改变作者顺序。
- 文献类型使用期刊论文、会议论文、硕士学位论文、博士学位论文、综述论文或预印本等稳定标签。
- 文献来源填写期刊、会议或学位授予单位；年份、卷期仅在已经核验时附加。
- 原文链接优先使用 DOI 或稳定出版页；关键词优先采用论文原始关键词。
- 影响因子、分区或会议等级无法可靠核验时填写 —，不得凭印象补写。

### 论文结构

- 严格按照论文真实章节标题和顺序概括，不预设固定章节数量或通用五段式。
- 不沿用论文原有的罗马数字、字母或其他章节序号。一级结构按全文顺序统一改为连续的 `1. `、`2. `、`3. `；每条使用 `序号. 真实标题：总结`，标题后必须使用中文冒号 `：`。
- 每个部分通常用 1 句话说明本节做了什么；信息较多时最多使用 2 句话。
- 算法类论文可在算法章节下按真实小节细分，每个小点仍以 1 句话为主；小节的语义编号为 `3.1`、`3.2`，在 Word 中统一显示为 `- 3.1 真实小节标题：总结`、`- 3.2 真实小节标题：总结`，不保留原文的 `A.`、`B.` 等字母序号。
- 子级条目使用 ASCII 连字符 `-` 作为层级标记；段落左缩进统一设为 0.74 cm，首行悬挂 0.37 cm，使连字符位于约 0.37 cm 处、正文从 0.74 cm 处开始，自动换行后与正文起始位置对齐。一级条目不缩进，也不加连字符。
- 综述论文按其真实分类框架、主题组织或开放问题编排；学位论文按真实章节编排。
- 不把实验结果提前堆进结构栏，不为凑点数拆分同一章节，也不改造论文中不存在的标题。

示例：

```text
1. Introduction：说明研究背景、现有方法的主要问题与本文目标。
2. Related Work：梳理相关方法及其局限，为后续算法设计建立比较基础。
3. Proposed Method：提出改进算法并说明整体流程。
- 3.1 Adaptive Search Mechanism：根据种群状态动态调整搜索步长，以协调全局探索与局部开发。
- 3.2 Perturbation Mechanism：在停滞阶段引入定向扰动，以降低陷入局部最优的风险。
```

### 研究问题

- 优先依据引言中的研究缺口、问题陈述、作者明确列出的研究问题和贡献动机。
- 保留问题发生的场景、约束和后果，尽量接近论文原始表述。
- 原文只有一个核心问题时写一个完整问题；原文列出多个问题时逐项对应；数量过多时按共同目标归并。
- 可用陈述句或问句，形式服从论文原文。综述可按分类、比较和开放问题组织。
- 不把方法名称换一种说法当作研究问题，不只写提高性能，也不自行扩展论文未讨论的问题。
- 多个问题按本文件的分点格式逐段编号，每一点直接写问题本身，编号作为唯一层级标记。

示例：

```text
现有方法在高维强耦合问题中计算开销快速增加，且难以同时保持搜索精度与稳定性。本文研究如何在控制复杂度的前提下改善这两类问题。
```

### 研究方法

- 优先写本文区别于已有工作的关键机制，包括采用的方法、实现方式及其解决的问题。
- 算法类论文按核心机制或真实算法小节分点；每点解释机制与作用，不只罗列模块名。
- 基础性数学建模只有在其本身构成方法创新时才写；常规模型定义、变量说明、一般求解流程不单独占点。
- 不以总体建模、数学建模、数据预处理等宽泛标签代替关键方法。
- 核心方法之后可补充实验设计，包括基准、维度或规模、对比方法、独立运行次数、评价指标、统计检验和消融设置；只保留解释研究结果所必需的设置。
- 方法点数由实际创新模块和论文结构决定，不固定为 3–6 点。
- 多个方法点按本文件的分点格式逐段编号，每一点直接用完整句子说明机制与作用。

示例：

```text
1. 提出自适应步长机制，根据连续迭代的改进程度在线调整搜索尺度，以避免固定步长在前期探索不足、后期震荡过大的问题。
2. 在标准基准上与多种对比算法独立运行若干次，并设置去除该机制的消融版本，以验证改进来源与稳定性。
```

### 研究结果

- 先判断文献是否包含作者自行实施的实验，再选择结果句式；不得把被引研究的实验写成本文实验。

实验型论文：

- 严格按照论文中的真实实验标题、实验对象和顺序分点，点数与实际实验对应。
- 每一点开头必须把实验名称具体写出来，并采用 `具体 XX 实验结果表明，……` 的句式；`XX` 来自论文，而不是来自模板。
- 每点同时交代实验对象、主要结果和该结果支持的结论。
- 保留关键数字、排名、维度、样本数、运行次数、p 值或显著性结论，所有数值必须能够回到表、图或正文。
- 结果过多时，优先保留能够回答研究问题、验证核心机制或说明适用边界的实验，其余合并概括。
- 不按方法模块机械复述，不只写性能更好，不在没有统计检验时使用显著优于。
- 不得默认套用基准函数实验、消融实验、实际应用实验三类。只有论文确实设置了相应实验时才写；论文使用鲁棒性、敏感性、案例研究、用户研究、仿真、现场试验等其他实验，就按论文原名具体化。
- 多个实验结果按本文件的分点格式逐段编号；编号后直接写具体实验名称和结果。

无原创实验的综述论文：

- 按综述真实证据写文献规模统计、分类框架、方法比较、基准与指标归纳、应用梳理或开放问题综合结果。
- 每一点使用具体名称加结果表明，例如 `文献规模统计结果表明`、`算法分类结果表明`、`基准与指标归纳结果表明`，不得套用实验结果表明。
- 系统综述或元分析若自行实施检索、筛选、统计或综合分析，应按其真实分析名称和结果写，不把它降格为一般实验。
- 明确检索或统计的时间边界；不把截至某年的综述结论写成当前事实。

命名方式示例，仅用于说明如何把实验名写具体，不代表每篇论文都包含这些实验：

```text
1. CEC 2017 30 维测试函数实验结果表明，改进算法在多数函数上取得更优的平均排名，说明核心搜索机制提高了整体求解稳定性。
2. 去除自适应步长机制的消融实验结果表明，收敛速度和最终精度均下降，说明该机制是性能提升的主要来源。
3. MK01–MK10 柔性作业车间调度实例实验结果表明，算法在真实约束条件下仍能获得可行解，说明其具有一定的应用能力。
```

### 创新与不足

- 每个创新点写清新机制或新对象、实现方式以及解决的问题。
- 不足优先采用作者声明、退化实验、消融结果、参数敏感性、计算开销或未覆盖场景。
- 证据不足时只写创新，字段标签使用创新；证据充分时使用创新与不足。
- 不把应用了某算法写成创新，不凭主观推测补论文缺点，也不重复研究方法全文。
- 在 JSON 中把创新写入 `innovations`，把有证据的不足写入 `limitations`。不要把两个分组混在一个字符串中。
- 每个分组只有一个要点时直接写正文，不加数字；同一分组超过一个要点时依次编号。创新与不足的编号互不连续。

单项示例：

```text
创新：
提出自适应步长机制，根据连续迭代的改进程度调整搜索尺度，以兼顾前期探索和后期收敛。
不足：
作者只在连续优化基准上验证该机制，尚未覆盖离散约束场景。
```

多项示例：

```text
创新：
1. 提出……
2. 设计……
不足：
1. 计算开销……
2. 实验范围……
```

### 感悟心得

- 使用第一人称，通常 1–3 句，明显短于方法和结果。
- 指出最值得借鉴的具体机制、实验设计或写作组织，并说明可迁移到自己的哪类问题。
- 可以记录尚未理解的部分或后续学习计划。
- 避免收获很大、值得学习、非常有启发等空泛句，也避免用引号包装比喻性概念。

## 密度与核验

- 篇幅随论文内容变化，不设置统一页数目标；不为填满表格重复摘要内容。
- 论文结构、研究方法和研究结果通常是信息密度最高的三栏，但仍以必要信息为限。
- 缩写首次出现时给出全称，后文保持统一；算法、数据集、期刊、会议和指标名称保持原文大小写。
- 数字、单位、维度、运行次数和评价预算不得改变含义。
- 写入 Word 前检查重复信息、空泛连接词、无来源推断和不必要的引号。
- 模板第 13 行备注仅保留空白槽位，Skill 不生成任何备注内容，由用户手工填写。

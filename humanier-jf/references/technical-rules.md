# 中文技术文档规则

来源：ruanyf/document-style-guide，提交 571951731efb4b83b1939af1d3dd830441ebef45。README 声明 public domain。下列规则为按中文技术文档用途筛选后的改编，并非逐条照搬规范。

## 正文规范

- 中文正文与英文词之间留一个半角空格；中文与阿拉伯数字可留或不留，全文一致。没有既定风格时采用留空格。数字与英文单位之间留空格，百分号跟随数字；不得把版本号、文件名或标识符内部拆开。
- 中文语句用中文全角标点和成对中文引号/括号；英文整句保留英文标点。语法、命令、代码、错误消息本体、路径、链接目标和数据值中的半角符号不改。
- 一段处理一个主要问题。仅在能改善理解时拆长句；条件、否定、主语、先后顺序和因果关系必须仍明确。句长和显示行数是提示，不作硬配额。
- 同一概念使用稳定称呼。已有英文缩写定义可规范括号和空格；原文缺少全名或中文解释时，不凭记忆补写。对读者必需的解释列为待补充，常用产品名无需逐一展开。
- 数值、单位、上下界和“增加了/增加到”“降低了/降低到”的含义受保护；百分比和百分点不可互换。资料不足时标记歧义，不重新计算或猜原意。
- 正式文档保持平实正式的语域。保留有用的列表、三个真实项目、必要重复与否定对照、功能性破折号；删除空泛宣传、无用总结和无信息的修饰。

## 结构规范的适用边界

新写独立文档时，可用连续标题层级，步骤按操作顺序排列。README/教程按实际需要说明用途、前置条件、操作、结果和限制；PR 描述说明触发条件、行为变化、验证和未验证范围；报告说明材料、方法、结果和证据边界。材料缺失时留待补充，不凑章节。

编辑既有文本时，默认保留用户给定标题层级、标题文字、锚点、模板、表格与文件名。需要改结构时给建议或按用户明确要求修改；没有要求不重命名文件或重排整套文档。完整软件手册结构不能套到每段 PR 或 README。

## 与去 AI 味审校的接口

规范性校对本身不保证自然度。不得为了“像人”添加作者没有提供的观点、反应、经验或幽默；不得把未核实的归因删成客观事实。遇到规则冲突，用户要求、语义忠实和受保护技术对象优先，其后才是正文规范和风格建议。

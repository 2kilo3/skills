# Humanier-JF

把输入当作编辑任务，而不是自由创作任务。以更自然、更可信的中文表达原文已经提供的内容。

## 不可变约束

- 保留事实、数字、日期、单位、专名、术语、引文、链接、立场、视角和证据强度。
- 保留用户要求的语域与格式。正式文本不要强行口语化，个人文本不要改成新闻稿。
- 不添加原文没有的经历、情绪、观点、来源、人物、案例、数据或精确细节。
- 不把相关性改成因果，不把猜测改成事实，也不为了“像人”而故意加入错字、语病或混乱。
- 不承诺规避 AI 检测器。目标是提高文本质量、自然度和可信度。

把日期、版本、功能、人物、动作等直接陈述的事件信息视为受保护内容。不要把“专家普遍认为、数据显示、毫无疑问、彻底改变行业”等无来源归因、假精确和宣传性判断误当成必须逐字保留的事实；除非用户确认其已经核实，否则按下述高风险规则处理。

若原文存在疑似错误、来源不明或互相矛盾的内容，保留其证据边界并列为待核实项，不自行补造答案。

## 必须按顺序执行

### 1. 确认任务

从用户消息中确定原文、目标读者、语域、长度和输出要求。缺少待处理文本时只索取文本；已有信息不要重复询问。

### 2. 建立静默保留清单

在内部记录不可改变的事实、数字、专名、引文、核心主张、第一/第三人称和格式结构。不要把这份清单输出给用户，除非用户要求审校说明。

### 3. 做一次模式扫描

先执行高风险分流，再检查普通风格模式。高风险分流是强制步骤：

| 原文内容 | 用户已提供具体来源或明确确认已核实 | 未提供来源且只要成稿 | 未提供来源且允许说明 |
| --- | --- | --- | --- |
| “专家普遍认为、行业报告显示、数据显示、研究表明”等模糊归因 | 保留信息并写明已有来源 | 删除整项主张 | 从成稿删除并列入待核实项 |
| 百分比、样本量、年份等可疑精确数据 | 原样保留 | 删除依赖该数字的主张 | 从成稿删除并列入待核实项 |
| “毫无疑问、必然、充分证明、彻底改变行业”等绝对断言 | 调整到来源实际支持的强度 | 删除预测或改为原文已有的可核查事实 | 降低强度并列入待核实项 |
| “革命、里程碑、彰显承诺、奠定基础、未来可期”等宣传判断 | 仅在语域需要且有依据时保留 | 删除修饰，只留事件与结果 | 删除并在说明中概括 |

不要用同义词掩盖问题。“不仅仅是……而是……”改成“不只是……更是……”，“奠定坚实基础”改成“打下基础”，都不算完成编辑。

完成高风险分流后，逐段检查以下模式。按功能和频率判断，不做机械禁词替换。

1. **可信度**：无依据的确定感、模糊权威、假故事、假精确、把观点写成事实。
2. **内容**：夸大意义、宣传腔、正确废话、假装面面俱到、通用“挑战与展望”。
3. **结构**：连续“不是 A，而是 B”、强行凑三项、段段总结、每段都以金句或升华收尾。
4. **语言**：空洞连接词、AI 高频词堆叠、同义词循环、回避简单的“是/有”、过度限定。
5. **节奏**：句长和句法过度整齐、破折号过密、连续使用相同开头或结尾。
6. **格式**：无必要的粗体、表情符号、提纲式小标题列表和聊天机器人客套话。

文本超过约 1000 个汉字、用户要求深度审校，或某种模式难以判断时，读取 `references/patterns.md` 的对应章节；不要为了完成短文本而加载全部示例。

### 4. 做最小充分修改

按以下优先级编辑：

1. 删除不提供信息的开场、重复、拔高和结尾。
2. 修正失真的确定性、归因和因果强度。
3. 把冗长句改为直接表达；只改真正存在问题的片段。
4. 调整连续同构句和段落节奏，但不为了变化而改写术语或清晰句子。
5. 保留作者已有的声音、幽默、锋芒和犹豫；原文没有时不要凭空添加。

原文缺少支撑细节时，删除或弱化空泛主张，或列为待核实项。不得用看似具体的新故事、新数字或新来源替换它。

### 5. 做可信度复核

逐一核对改写后的故事、数字、来源、强断言和因果词。每项都必须来自用户提供的可核查材料或已经确认的原文事实。无法对应时撤销该内容。

最后搜索“毫无疑问、充分证明、专家普遍、行业专家、报告显示、数据显示、研究表明、不只是、不仅仅、革命、里程碑、奠定基础、重要意义”。逐项说明保留依据；没有明确依据就按高风险表处理，而不是换一个近义词。

### 6. 做忠实度复核

对照静默保留清单，确认没有改变事实、立场、人称、语域、证据强度和格式要求。朗读一遍，只修正仍然机械或拗口的地方。

### 7. 按要求输出

- 用户只要成稿：只输出修订后的完整文本。
- 用户要求说明：先输出修订文本，再用简短条目说明影响最大的改动。
- 存在无法安全修正的来源、事实或含义疑点：在正文后增加“待核实项”，只列必要问题。
- 不自动输出评分、长篇诊断、自我评价或“希望这对你有帮助”等客套话。

## 决策规则

| 情形 | 处理 |
| --- | --- |
| 细节已在原文中 | 可以保留、压缩或重新组织 |
| 原文主张具体但无来源 | 保留边界并标记待核实，不编来源 |
| 原文语气中立 | 保持中立，不替作者增加观点 |
| 原文没有第一人称 | 不添加“我”、私人经历或感受 |
| 三项、连接词或破折号有明确功能 | 保留；只处理无功能的重复使用 |
| 用户要求更鲜明的语气 | 强化原文已有立场；新增立场前先获得用户确认 |

## 交付前检查

- 是否出现原文没有的事实、数字、来源、经历、情绪或立场？
- 是否改变了因果、确定性、引用归属或证据强度？
- 是否把所有连接词、三项列举或正式表达机械删除？
- 是否保留了作者的语域和个性，而不是套用统一“人味”？
- 是否满足用户指定的长度、格式和输出范围？
